## Design

One placer decides per request; zb.sh and the pre-push hook ask it. Sessions never choose.

### What goes where
- To the gpu-box when it qualifies: test (incl. filtered), ci. ~3x faster there than a
  quiet Mac, and off the Mac's cores and swap. lab builds already go there
- test-ui: Mac, unless the Mac's load is over its cores (then 28 s here vs ~5 s there
  with the sync)
- Stays on the Mac: the deploy build (ReleaseSafe LLVM: 185 s here vs 230 there, and
  the Mac gets quieter once tests and ci leave), dev-watch (needs a macOS binary),
  ui-*-size steps, the commit hashes tree, anything with a local artefact
- ci there skips shellMac (build.zig already only adds it on a macOS host); a new
  `zig build ci-mac` step (shellMac only, 1 slot) runs on the Mac beside it; both must
  pass. Tests run as x86_64-linux there: closer to the box than aarch64-macos. Option
  later: the app's Windows tests through WSL interop (the gpu-box is Windows)

### deploy/place.sh KIND (new)
Prints `gpu-box` or `mac` and why, one line. gpu-box qualifies when all of:
- not off: `deploy/place.sh off|on` (Jacob: "gpu-box off for a long while"; a file in
  ~/.cache/meiolol-place), MEIOLOL_WHERE=mac|gpu-box per call wins
- answers ssh in 3 s (ControlMaster socket kept 10 min, so later probes cost ~20 ms)
- League down per the watcher, whose last line is under 2 min old (else unknown = no)
- its build queue is short: free build slot, or one waiter
Otherwise mac. No cost model: test and ci are faster there even against an idle Mac,
so they go whenever it qualifies.

### deploy/remote-build.sh (new): run there, look local
- Working tree: rsync --files-from (git ls-files -co) to ~/ml/build/tree.K, K fixed per
  kind (test, test-ui, ci; zig-pkg kept, cache ~/ml/build/cache). Commit: git push to
  ~/ml/build/repo.git, worktree ~/ml/build/wt.K at the sha (check-deploy.sh needs git)
- Runs as `systemd-run --user` unit meiolol-build-ID (outlives ssh; linger is on), nice
  0, in its own build slot resource (~/ml/locks/build.slots, 2), log and exit code in
  ~/ml/build/jobs/ID. Touches ~/ml/awake.d/build while running, so Windows stays awake
- Client follows the log over ssh, rewrites the tree path to the Mac's root in each line
  (errors stay clickable), exits with the job's code. Exit 75 = not done there
  (unreachable, preempted, no slot within 60 s): the caller runs it on the Mac
- League: lab-watch.sh stops build units (TERM), not pause: a paused build would hold a
  session or a push. The client sees 75 and falls back. No new builds while League is up
- Sleep or WSL restart mid-build: ssh drops; the client probes for 30 s, then 75. A unit
  that outlived it finishes and its result is dropped (logged)
- Prune ~/ml/build/cache past 40 GB when no build runs (as zig-cache-prune.sh)

### Outputs match
Same zig 0.17.0 (pinned) and explicit -Dtarget/-Dcpu: 96's deploy build on both hosts
has byte-identical .text, .rodata and .data; only debug-info source paths differ. ci's
cross builds (Windows, Linux, wasm, lab) are checks, not shipped, so that is enough;
the deploy build stays on the Mac anyway. Native test binaries differ by design (host
target). zstd, shellcheck and nodejs installed on the gpu-box (deploy/gpu-box.sh
install, apt via `wsl.exe -u root`); remote-build.sh prints their versions with the
result so a lint gap shows.

### One view: deploy/compute.sh status (new)
```
mac      load 24.1/10  swap 10.2 GB  slots 5/6 held, 2 waiting  zig compiles 9 (3 outside slots: dev-watch, ...)
gpu-box  up  League down  awake  load 1.3/20  build 1/2 (test, 40 s)  lab cpu 3/9 gpu 0/3, queue 0
placing  test, ci -> gpu-box; test-ui, deploy build -> mac
```
Reads slots.sh state, ps, the gpu-box's locks and jobs in one ssh. "Outside slots" names
the zig processes no slot holder owns (today's pileup was partly those).

## What changes in the frozen files (after Jacob's yes)

- zb.sh: before taking Mac slots, `place.sh KIND`; gpu-box: remote-build.sh with the same
  args; on 75 queue for Mac slots as now. The answered-by-a-later-run logic is
  unchanged (a remote run synced the files at its start, as a local one reads them)
- slots.sh: no change to the gate. `status` adds a line pointing to compute.sh. Slots
  stay 6; once tests and ci leave, 96's -j cap per weight is what keeps the Mac usable
- pre-push hook: ci through place.sh: on the gpu-box from the commit plus ci-mac on the
  Mac; 75 or unreachable: Mac ci in 3 slots as now. Event text says where it ran
- push.sh: none (the hook does it); its --status shows where the last ci ran
- build.zig: one step, ci-mac (shellMac). The rest of build.zig is 96's
- box.sh, commit.sh: none
- lab-watch.sh: stops meiolol-build-* units when League is up
- gpu-box.sh install: zstd, shellcheck, nodejs, ~/ml/build, the lock files

## Order (each step usable alone)
1. compute.sh status (read-only, no frozen file)
2. remote-build.sh + place.sh, used by hand (`deploy/remote-build.sh test`), gpu-box
   install (zstd, shellcheck, nodejs); checked against 96's numbers
3. zb.sh test through them (Jacob's yes)
4. pre-push ci + ci-mac (Jacob's yes)
Independent of 96's comptime fix: with it, gpu-box test is 47 s, without 150 s (still
under the loaded Mac's 440-617)
