# Token names

An explanation of Primer's design token naming convention

## [Intro](https://primer.style/product/primitives/token-names/#intro)

Primer design tokens are named using a consistent convention to make it easier to understand what they do and how they should be used at a glance.

## [Categories](https://primer.style/product/primitives/token-names/#categories)

This naming convention is broken down into three categories: **base, component/pattern, functional**. Each category is a subset of the over-arching convention.

Across all categories, the [property](https://primer.style/product/primitives/token-names/#property-required) value is always required. This value specifies exactly how a token is indended to be applied to a UI.

### [Base](https://primer.style/product/primitives/token-names/#base)

Base tokens are the lowest level tokens and map directly to a raw value.

#### [Example `base` tokens](https://primer.style/product/primitives/token-names/#example-base-tokens)

```
base-size-4
base-color-green-5
brand-base-color-lime-5
base-fontWeight-semibold
```

### [Functional](https://primer.style/product/primitives/token-names/#functional)

Functional tokens represent global UI patterns.

#### [Example `functional` tokens](https://primer.style/product/primitives/token-names/#example-functional-tokens)

```
bgColor-inset
borderColor-default
brand-borderWidth-thin
boxShadow-inset-thick
```

### [Component/pattern](https://primer.style/product/primitives/token-names/#componentpattern)

Component/pattern tokens should only be used in component CSS.

#### [Example `component`/`pattern` tokens](https://primer.style/product/primitives/token-names/#example-componentpattern-tokens)

```
control-danger-borderColor-rest
button-primary-bgColor-hover
brand-overlay-bgColor
text-codeInline-fontSize
```

## [Convention breakdown](https://primer.style/product/primitives/token-names/#convention-breakdown)

### [Prefix](https://primer.style/product/primitives/token-names/#prefix)

Prefix provides top-level encapsulation of a particular flavor of Primer, such as Primer Brand. It can be used for protected base tokens like Brand color scales, or value overrides for traditional Primer tokens in order to avoid collisions.

`brand`: used for marketing/brand specific tokens.

### [Namespace](https://primer.style/product/primitives/token-names/#namespace)

Namespace creates a scope used to identify how a token may be used. For example, `base` tokens are the lowest level and are generally used as a reference for functional tokens (the next step above).

`base`: represents global, constant values. These are the lowest level tokens and map directly to a raw value.

### [Pattern](https://primer.style/product/primitives/token-names/#pattern)

Pattern represents a group of design decisions, or a specific Primer component. Whenever possible, aim to use a name that is generic enough to influence related components. For example, the pattern `control` can be used for multiple types of controls like buttons, inputs, or interactive ActionList items.

For pattern and component names that are multi-word, use camelCase to separate each word.

### [Variant](https://primer.style/product/primitives/token-names/#variant)

Variant can be used to either modify the **pattern** or **property**. Only one variant is allowed per token. It typically represents a stylistic variant of a token such as color (danger) or size (small).

### [Property (required)](https://primer.style/product/primitives/token-names/#property-required)

Property is used to represent an item’s style. It usually matches a [CSS property](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference#index), but it can also store other conceptual definitions such as `size`, `minTarget`, etc. Use camelCase for multi-word properties.

### [Scale](https://primer.style/product/primitives/token-names/#scale)

Scale represents ordinals to describe things like state, density, thickness, range, and speed. Scale names strive to follow our [size naming convention standards](https://github.com/github/primer/blob/main/adrs/2022-02-09-size-naming-guidelines.md).

### [Token name block delimiters](https://primer.style/product/primitives/token-names/#token-name-block-delimiters)

Individual name blocks for each token should be separated with a single character that is relevant to each Primer framework. For example, use the `-` dash character for CSS variables and `.` dot character for JavaScript.

Do

Use dashes to separate words.

Don’t

Don't use other characters to separate words.

## [Color modifiers](https://primer.style/product/primitives/token-names/#color-modifiers)

We use the following values to modify the color [variant](https://primer.style/product/primitives/token-names/#variant):

-   `default` - The default color variant for a given token. Example: `fgColor-default`
-   `muted` - The secondary color variant for a given token. Example: `fgColor-muted`
-   `emphasis` - The opposite of "muted", emphasis is a stronger color variant. Example: `bgColor-accent-emphasis`

## [Size modifiers](https://primer.style/product/primitives/token-names/#size-modifiers)

Size modifiers are often found as part of the [scale](https://primer.style/product/primitives/token-names/#scale) block. The following describes how we name size modifiers for each category.

### [General-purpose t-shirt sizes](https://primer.style/product/primitives/token-names/#general-purpose-t-shirt-sizes)

```
xsmall | small | medium | large | xlarge | xxlarge
```

### [Density](https://primer.style/product/primitives/token-names/#density)

Use `normal` as the default size

```
condensed | normal | spacious
```

### [Thickness names](https://primer.style/product/primitives/token-names/#thickness-names)

Use `thin` as the default size

```
thin | thick | thicker
```

### [Viewport ranges names](https://primer.style/product/primitives/token-names/#viewport-ranges-names)

```
narrow | regular | wide
```
