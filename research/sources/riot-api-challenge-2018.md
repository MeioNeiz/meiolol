# The Riot Games API Challenge 2018 (Riot DevRel, 2018-12-19)

Why: what Riot itself said it rewards in third-party League tools, in its own judging
criteria.

## Assessment

- Evidence: A. Riot's own DevRel page, dated Dec 19 2018, still live on riotgames.com.
- Reasoning: strong. Explains why each category exists and why documentation matters.
- Interests: Riot (promoting its developer ecosystem and the then-new LCU access).
- Weigh: eight years old; criteria show DevRel values (social, community benefit,
  documentation), not current production key rules. Last LoL API Challenge found so far.

## Findings

- [policy] [tools] Prompt: build on the League Client APIs, in one of three categories:
  Entertainment, Usability/Practicality, Creativity/Originality. ^f1
  > Submit a project that utilizes the League Client API’s and falls in one of the following categories.
- [policy] [fun] Entertainment category explicitly favours social experiences with
  friends and sharing. ^f2
  > Hint: Social experiences that allow you to involve friends or share your experiences are a big plus.
- [policy] Usability: Riot wants tangible benefit to the whole community, lasting past the
  contest; notes past winners skewed utility. ^f3
  > We’ll be looking for submissions that will provide a tangible benefit to the entire community and will hopefully continue to provide value to players even after the contest ends.
  > Many of the winning submissions in the past have fallen within this category
- [policy] Creativity category rewards breaking convention over iterating on successful
  ideas. ^f4
  > this category is meant to reward the individuals who aren’t afraid to challenge convention in pursuit of new and revolutionary ideas
- [policy] Judging criteria: technical difficulty, clarity/presentation, documentation,
  polish; public GitHub repo required. ^f5
  > All entries will be required to provide a public GitHub repo link as part of their submission.
  > Technical difficulty
  > Project documentation
- [policy] DevRel goal: strengthen the developer community; document technologies and
  lessons learnt. ^f6
  > One of the goals for each API Challenge is to strengthen and empower the developer community as a whole.
- [policy] [data] Rule: no project acting as an alternative data source or redistribution
  database (echoes the current no-data-broker rule, [[riot-docs-lol#^f3]]). ^f7
  > Your project should not offer itself as an alternative source of data apart from the Riot Games API (e.g., please don’t create a database of info with the intention of redistribution).
- [policy] Temporary production keys were offered to entrants on request with a full
  concept description. ^f8
  > A temporary production API key may be granted in order to aid in the development of a submission.
- [fun] Prizes: RP plus work highlighted on Riot and League web pages. ^f9
  > Work highlighted on certain Riot Games and League of Legends web pages
