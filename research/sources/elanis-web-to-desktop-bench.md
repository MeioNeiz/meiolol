# Web to Desktop framework comparison (Elanis), README benchmarks

Why: independent numbers for Electron vs system-webview footprints, on Windows.

## Assessment

- Evidence: B. Created Mar 2021, 2.0k stars, 54 forks, 10 contributors, MIT, pushed Oct
  2026; numbers regenerated by its runner on GitHub CI.
- Reasoning: fair. States its own error margin (single CI runs, system load); empty
  apps only.
- Interests: none known; not tied to a framework.
- Weigh: process-tree memory sums each process's memory (`pidusage`), so shared pages
  are counted more than once for multi-process engines; the free-memory delta is noisy
  (a negative value appears for Tauri on macOS). Use for order of magnitude only.

## Findings

- [gui/webview] Method: empty app, measured on GitHub CI; the author warns the numbers
  carry a margin of error. `README.md` ^f1
  > These benchmarks are done on GitHub CI.
  > You should read these tables as a comparison between frameworks for the same OS, architecture, and app, with a margin of error.
- [gui/webview] Windows x64 empty-app build size: Electron about 385 MB, Tauri about 3 MB,
  Wails about 11 MB, Neutralino about 2 MB. `README.md` ^f2
  > | ***Windows (x64)*** | ≈385MB | ≈3MB | ≈563MB | ≈11MB | ≈171MB | ≈2MB | ≈25MB | N/A<sup>1</sup>|
- [gui/webview] Windows x64 release memory, summed over the process tree: Electron about
  279 MB, Tauri (WebView2) about 307 MB, Wails (WebView2) about 317 MB: no saving on
  Windows. `README.md` ^f3
  > | ***Windows (x64)*** | ≈365MB (Debug) => ≈279MB (Release) | ≈454MB (Debug) => ≈307MB (Release) | ≈227MB (Debug) => ≈461MB (Release) | ≈530MB (Debug) => ≈317MB (Release) |
- [gui/webview] By drop in free system memory, Windows release: Electron about 100 MB,
  Tauri about 187 MB, Wails about 206 MB. `README.md` ^f4
  > | ***Windows (x64)*** | ≈219MB (Debug) => ≈100MB (Release) | ≈217MB (Debug) => ≈187MB (Release) |
- [gui/webview] On macOS and Linux the system webview apps use far less memory than
  Electron (Tauri about 96 MB vs Electron about 364 MB on macOS arm64). `README.md` ^f5
  > | ***MacOS (arm64)*** | ≈460MB (Debug) => ≈364MB (Release) | ≈231MB (Debug) => ≈96MB (Release) |
- [gui/webview] Windows release start time: Electron about 153 ms, Tauri about 576 ms,
  Wails about 537 ms. `README.md` ^f6
  > | ***Windows (x64)*** | ≈530ms (Debug) => ≈153ms (Release) | ≈4678ms (Debug) => ≈576ms (Release) |
- [gui/webview] Memory is the sum over the app process and its child process tree via
  pidtree and pidusage. `runner/runner.js` ^f7
  > pids = [childProcess.pid, ...(await pidtree(childProcess.pid))];
  > stats = await pidusage(pids);
- [gui/webview] (inferred) On Windows a WebView2 app saves download size (MBs vs hundreds
  of MB), not RAM: the Chromium process set costs about what Electron's does. A Zig host
  removes only the small host share. ^f8
- [gui/webview] Checked, not there: no CEF, Dear ImGui or native Win32 baseline. ^f9
