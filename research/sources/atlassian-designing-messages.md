# Atlassian Design System: Designing messages

Why: Atlassian's rules for where status and help text may appear, and any limits.

## Assessment

- Evidence: A. Atlassian's design system for Jira, Confluence and others.
- Reasoning: fair. A component table per message type, little explanation.
- Interests: none.
- Weigh: no word or character limits on this page.

## Findings

- [ux/layout] Banners are reserved for critical system-level messages. Banner ^f1
  > Use banners only for critical system-level messaging for example, warnings about loss of data or functionality.
- [ux/layout] Banners push the page down. Banner ^f2
  > Banners appear at the top of the screen and shift the content below them.
- [ux/layout] Inline messages show an icon and short message; the full message opens on
  interaction (progressive disclosure). Inline message ^f3
  > People can interact with the icon, title, or secondary text to reveal the full inline message.
- [ux] Each message type has a fixed component and style, so people know what to expect. Choose a message type ^f4
  > Each message type has a consistent visual and writing style to help people know what to expect.
- [ux] Checked, not there: no word or character limits on this page. ^f5
- [ux/layout] (inferred) meio.lol's site-wide preview banner is not a critical
  system-level message by this rule; a one-line chip or footer note fits it. ^f6
